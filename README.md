## Установка

Плагина нет в каталоге сообщества: он в бете и ставится через
[BRAT](https://github.com/TfTHacker/obsidian42-brat).

1. Поставьте BRAT из каталога сообщества и включите его.
2. Команда **BRAT: Add a beta plugin for testing**.
3. Впишите `Blysspeak/vaultwire`, отметьте установку последней версии.
4. Включите vaultwire в списке сторонних плагинов.

Дальше BRAT сам подтянет обновления. Способ работает и на телефоне, без проводов и файловых
менеджеров.

Установка вручную: возьмите `main.js`, `manifest.json` и `styles.css` из
[релиза](https://github.com/Blysspeak/vaultwire/releases) и положите в
`<хранилище>/.obsidian/plugins/vaultwire/`.

> Плагин работает только с сервером vaultwire: своим или того, кто выдал вам код подключения.
> Никаких сторонних сервисов он не использует и никуда больше не ходит.

## Что внутри

Проект состоит из трёх частей:

- `plugin/` — плагин Obsidian (TypeScript, esbuild). Ставится на десктоп и на мобильные устройства.
- `server/` — сервер синхронизации (Fastify, Prisma, PostgreSQL). Разворачивается на своей машине.
- `shared/` — общие типы протокола, чтобы контракт клиента и сервера не разъезжался.

## Как это работает

Пространство (space) — это набор файлов, который синхронизируется между участниками команды. Каждый участник подключает пространство в отдельную папку своего хранилища. Пространств может быть несколько, у каждого своя роль участника.

Вход состоит из двух секретов:

1. Код подключения, который выдаёт владелец пространства. В нём зашиты адрес сервера, идентификатор пространства и одноразовый инвайт.
2. Пароль шифрования, общий на команду. Передаётся вне плагина.

Из пароля выводятся ключи шифрования содержимого, метаданных и адресации. Сервер хранит только шифротекст: он не знает ни содержимого заметок, ни их имён, ни структуры папок.

## Роли

- `owner` — создатель пространства. Выпускает инвайты, отзывает устройства, видит список участников.
- `rw` — чтение и запись.
- `ro` — только чтение. Локальные правки не отправляются и не затираются молча: при расхождении локальная версия сохраняется рядом отдельным файлом.

## Возможности плагина

- **Мастер подключения** в три шага: код подключения, локальная папка, пароль. Перед записью
  показывается план: сколько файлов придёт, сколько уйдёт, сколько конфликтов и какой объём.
  До подтверждения плагин не трогает ни диск, ни настройки.
- **Запоминание пароля** на устройстве, включено по умолчанию: подключение поднимается при запуске
  Obsidian само, без окна. При включённой опции пароль хранится в открытом виде в `data.json`
  плагина внутри хранилища, поэтому папку конфигурации Obsidian нельзя синхронизировать сторонними
  средствами. Опция выключается в настройках подключения, выключение стирает сохранённый пароль.
- **Создание пространства** для владельца: заводит пространство на сервере, ставит верификатор
  пароля и заливает первичный снимок выбранной папки. Кнопка видна при заданном bootstrap-токене.
- **Двусторонняя синхронизация** с трёхсторонним сравнением: правки идут по событиям хранилища
  и по сверочному скану, переименование уезжает одним запросом, а не парой «удалить и создать».
- **Живой канал** WebSocket с откатом на интервальный опрос: сервер шлёт звоночек, данные всегда
  тянутся по HTTP.
- **Конфликты**: по умолчанию конфликтная копия рядом, опционально трёхстороннее слияние markdown
  (frontmatter и бинарные файлы всегда уходят в копию) или «побеждает свежий». Незакрытые конфликты
  живут в панели с кнопками «оставить мою», «оставить серверную» и «открыть обе рядом».
- **Корзина и история**: удаление это надгробие, тело живёт срок хранения, восстановление
  создаёт новую ревизию и не переписывает историю.
- **Защита от массовых операций**: прогон, собравшийся удалить слишком много, останавливается
  и показывает список.
- **Боковая панель** с вкладками активности, конфликтов и корзины плюс строка состояния:
  иконка, состояние и очередь, клик открывает панель.
- **Команды**: синхронизировать сейчас, открыть панель, показать конфликты, убрать конфликтные
  копии, подключить пространство, ввести пароль подключения. Горячие клавиши не назначаются.
- **Работа офлайн**: изменения копятся с флагом `dirty` и уезжают при появлении сети; хранилище
  не блокируется никогда. Подключения без сохранённого пароля спрашивают его один раз после
  запуска Obsidian.
- Интерфейс русский, все строки собраны в `plugin/src/i18n/`. Node и Electron API не используются,
  `isDesktopOnly` остаётся `false`: плагин работает и на мобильных устройствах.

## Разработка

Нужны Node 22 и PostgreSQL 16. Пакеты ставятся по отдельности, `shared` подключён к остальным
через `file:../shared`, поэтому ставить и собирать его надо первым.

```
cd shared  && npm install && npm run build
cd ../server && npm install
cd ../plugin && npm install
```

`shared` компилируется в `dist`, а сервер и плагин импортируют именно его. После правки схем
протокола пересоберите пакет, иначе соседи будут видеть старые типы:

```
cd shared && npm run build
```

### Сервер

```
cd server
cp .env.example .env      # заполнить DATABASE_URL и BOOTSTRAP_TOKEN
npm run generate          # клиент Prisma
npm run migrate           # миграции на локальную базу
npm run dev               # tsx watch, слушает PORT из .env
```

Подробности по базе, миграциям и переменным окружения — в `server/README.md`.
Развёртывание на боевой машине (nginx, pm2, TLS, бэкапы, откат) — в
[`server/deploy/README.md`](server/deploy/README.md).

### Плагин

```
cd plugin
npm run dev               # esbuild в режиме watch
npm run build             # проверка типов и сборка main.js
```

Сборка кладёт `main.js` рядом с `manifest.json`. Для проверки в Obsidian скопируйте
`main.js`, `manifest.json` и `styles.css` в `<хранилище>/.obsidian/plugins/vaultwire/`
либо сделайте символическую ссылку на каталог `plugin`.

Корневой `styles.css` собирается склейкой из `plugin/styles/*.css` (Obsidian требует один файл,
а правило проекта ограничивает длину файла). Правьте части, не результат: сборка перезапишет его.

### Спецификации

Спеки фич ведутся через [spec-kit](https://github.com/github/spec-kit). Шаблоны и конституция
проекта лежат в `.specify/`, а команды агента ставятся локально и в репозиторий не коммитятся:

```
uvx --from git+https://github.com/github/spec-kit.git specify init --here --integration claude --script ps
```

### Проверки

```
cd shared && npm run typecheck
cd server && npm run typecheck && npm test
cd plugin && npm run typecheck && npm test
```

Тесты сервера и плагина не требуют базы данных: всё, что ходит в PostgreSQL, проверяется
отдельными сценариями против живой базы.

## Развёрнутый экземпляр

`https://obsidian.boostix.space` — сервер команды. Поднимается скриптом
`server/deploy/install.sh`, работает под pm2 как `vaultwire-server`, слушает
`127.0.0.1:8787` за nginx. Проверка живости: `https://obsidian.boostix.space/health`.

## Куда плагин ходит по сети

Только на тот сервер, который вы указали при подключении. Ни аналитики, ни телеметрии,
ни обращений к сторонним сервисам в плагине нет. На сервер уходят: шифротексты файлов,
зашифрованные метаданные, токен вашего устройства и счётчик изменений.

Пароль шифрования на сервер не отправляется никогда. Ключи выводятся на устройстве,
и сервер не может прочитать ни содержимое заметок, ни их имена, ни структуру папок.

## Статус

Бета. Сервер работает, синхронизация между двумя устройствами проверена вживую:
